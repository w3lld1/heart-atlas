# ReportExplorer: разбор заключения ЭхоКГ

Дата: 14.10.2026. Поток «Интерактив для статей». Issue: создать при PR 1 (продолжение #330, раздел «PR 2» в `2026-10-14-editorial-carry-over.md`).

## Что это

Учебный образец заключения трансторакальной эхокардиографии внутри статьи «Эхокардиография». Читатель (пациент или студент) видит типичные разделы заключения и термины, раскрывает термин и читает, что это слово значит, простыми словами, с источником и ссылкой на статью сайта.

Компонент **объясняет слова**. Он не толкует ничьи значения и не помогает оценить собственное заключение.

## Жёсткие ограничения

1. Нет загрузки файлов, полей ввода, вставки текста; ничего о читателе не сохраняется (ни `localStorage`, ни cookie, ни аналитика). На странице нет `<form>` и `<input>`.
2. Нет вердикта «норма/патология», нет порогов и диапазонов, по которым можно оценить своё заключение, нет индивидуальных советов.
3. **В образце нет чисел.** Вместо значений стоит нейтральная заглушка «…» с подписью «значение в образце не указано». Обоснование: даже помеченное вымышленное число рядом с «ФВ ЛЖ» читатель воспримет как ориентир и сравнит со своим; качественные слова («снижена», «умеренная») в строке образца — тоже оценка. Поэтому строка образца содержит только название параметра, а смысл раскрывается в пояснении. Unit-тест запрещает цифры в тексте строк образца (кроме номеров `<Cite>`).
4. Каждое пояснение состоит только из предложений, которые уже есть в статьях сайта (с их `<Cite>`), или из источников `content/trusted-sources.yaml`, проверенных по тексту. Термин без источника выбрасываем.
5. Над образцом плашка «Вымышленный учебный пример. Это не разбор вашего исследования: заключение оценивает врач вместе с жалобами, осмотром и другими исследованиями». Вторая часть фразы пересказывает предложение из раздела «Что значат результаты» статьи; своего `<Cite>` у него нет, а плашка — UI-строка, поэтому без `<Cite>`.

## Что взяли из PR #335 и почему он закрыт

Стек #331–#337 закрыт мейнтейнером (комментарий в #331): проверка рецензий в сборке блокировала новые статьи без врача, `publication: 'draft'` по умолчанию скрыл бы статьи, проверка порядка источников запрещала их правку, service worker стирал офлайн-кэш, база конфликтовала с main. В самом #335 обсуждения нет. ReportExplorer там же назван тем, что переносим отдельной спекой.

Полезно из `feat/editorial-guided-report` (`apps/web/src/components/interactive/ReportExplorer.astro`):
- нативный `<details>`/`<summary>` на термин: клавиатура и скринридеры без JS;
- плашка «вымышленный пример» с `role="note"`;
- раскрытие всех пояснений при печати;
- e2e: ширина 320 px без горизонтальной прокрутки, работа без JS, печать.

Не берём: sidecar-файлы `*.interactive.yaml` и схему `InteractiveBlock` (данные отдельно от текста, свои ссылки на источники в обход `<Cite>`), `schemaVersion`/`publication`/`id` источников, тестовые статьи-фикстуры, `border: 1px solid` и т. п. без проверки темы. Поля «пример значения» (`term.example`) нет: см. ограничение 3.

## Дизайн

**Где живёт.** Встроен в статью `content/{ru,en}/diagnostic/echocardiography.mdx`, раздел «Что значат результаты», после текста Patient/Student. Отдельной страницы нет: пояснения цитируют источники статьи, а `<Cite>` работает только внутри статьи. В embed-версии статьи компонент работает так же (он статичен).

**Компоненты** (`apps/web/src/components/report/`), регистрируются в `article-components.ts`:

```mdx
<ReportExplorer>
  <ReportSection title="Левый желудочек">
    <ReportTerm term="Фракция выброса ЛЖ" article="disease/heart-failure">
      Предложения из статьи с <Cite n={…} />.
    </ReportTerm>
  </ReportSection>
</ReportExplorer>
```

- `ReportExplorer.astro` — `<section aria-labelledby>` с заголовком `h3` (строка из messages), плашкой, списком разделов. Работает только на странице статьи (`Astro.locals.article`, иначе ошибка сборки, как у `<Quiz />`).
- `ReportSection.astro` — подзаголовок раздела образца (`h4`) и список `<ul role="list">` строк.
- `ReportTerm.astro` — строка `<li><details><summary>{term}: «…»</summary>…</details></li>`. В пояснении: слот (текст статьи), ссылка «Подробнее: <название статьи>».
- Проверки при сборке (ошибка, как в `Cite`/`Structure`): в слоте `ReportTerm` есть хотя бы один `<Cite>` (по отрендеренному `Astro.slots.render`); `article` существует в коллекции `articles` для локали контента (`Astro.locals.article.locale`), название — из её frontmatter; ссылка — `localePath(import.meta.env.BASE_URL, Astro.locals.locale, 'disease/heart-failure/')`, то есть в языке страницы, как относительные ссылки в тексте статьи.

**Тексты.** Названия разделов, терминов и пояснения — контент статьи в MDX каждой локали (переводятся вместе со статьёй, работают fallback-правила контента). В `messages/<locale>.json` (эталон `en.json`) только UI: `report.title`, `report.fictional`, `report.placeholder`, `report.more`. Если статья показана в fallback-языке, блок наследует `lang` от `<article>` страницы, а UI-строки получают `lang={Astro.locals.locale}` (как заголовок `<Quiz />`).

**JS: 0 байт.** Ни `<script>`, ни острова. Раскрытие — `<details>`. `:target`/`<dialog>` не нужны: `<dialog>` требует JS для открытия, `:target` ломает «назад» и прокрутку. Бюджет `scripts/js-budget.ts` не меняется, поэтому реализация **не ждёт #425**. Если на ревью захотят JS (например «раскрыть все»), это отдельный PR после #425.

**CSS.** Только логические свойства (`margin-block`, `padding-inline`, `border-inline-start`), цвета из токенов темы, `summary` с видимым `:focus-visible`. Печать: в `@media print` пояснения видны и у закрытых `details` (`details::details-content { content-visibility: visible }`, как в #335). В браузерах без `::details-content` закрытые термины печатаются свёрнутыми; это допустимо, JS ради печати не добавляем. e2e проверяет печать в Chromium. Без анимаций.

**Доступность.** `summary` фокусируется Tab, Enter/Space раскрывают, скринридер объявляет «свернуто/развернуто». Плашка — `role="note"`. Заглушка «…» имеет видимую подпись, а не только `aria-label`. Порядок заголовков: h2 раздела статьи → h3 образца → h4 разделов. Контраст по токенам. Пояснения не индексируются (пункт 2 выбора по умолчанию).

**Сознательно не берём** (дают пороги для самооценки): группы ФВ 40 / 41–49 / 50% (`disease/heart-failure`, Student); «здоровый желудочек выбрасывает больше половины крови» (`anatomy/cardiac-cycle`) — скрытая норма ФВ; признаки тяжёлой АН (vena contracta, PHT, объём регургитации, `disease/aortic-regurgitation`); градации выпота по миллиметрам (`disease/pericardial-effusion`); пороги NT-proBNP.

**Выброшены, нет источника на сайте:** диастолическая функция (E/A, E/e′), давление в лёгочной артерии (СДЛА), размеры аорты, ИММЛЖ, фракция укорочения, градиент на клапане. Вернём, когда в статьях появятся проверенные предложения без порогов.

## Плашка «Врачом не проверено»

Статья «Эхокардиография» имеет `review: null`, плашка `ReviewNotice` наверху статьи остаётся и покрывает компонент: образец и пояснения — часть статьи, не проверенной врачом. Компонент не убирает и не дублирует плашку; его собственная плашка «вымышленный пример» говорит о другом (это не ваше исследование). Когда у статьи появится `review`, обе плашки ведут себя по-своему: «Врачом не проверено» исчезает, «вымышленный пример» остаётся всегда.

## Тесты

- Unit (`apps/web/test/report-explorer.test.ts`): в строках образца ru/en нет цифр; у каждого `ReportTerm` есть `<Cite>`; все `article` существуют; набор ключей `report.*` есть в `en.json` (и `i18n:check` для остальных).
- Ошибки сборки на фикстурах: `ReportTerm` без `<Cite>`, несуществующая `article`, `ReportExplorer` вне статьи.
- e2e (`apps/web/e2e/report-explorer.spec.ts`), для каждой локали из реестра: термин раскрывается с клавиатуры (Tab, Enter), остальные закрыты; ссылка «Подробнее» ведёт на страницу под `BASE_URL`; 320 px без горизонтальной прокрутки; без JS всё работает; печать показывает все пояснения; на странице нет `input`/`form` внутри блока; `axe(page)` без нарушений в закрытом и раскрытом состоянии; RTL-сборка (`HA_TEST_LOCALES=1`): отступы зеркалятся.
- JS: unit-тест (Container API) проверяет, что в HTML `ReportExplorer`, `ReportSection` и `ReportTerm` нет `<script>`; `js-budget` проходит с прежним бюджетом.

## Выбор по умолчанию (2026-10-14, тред интерактива)

Это выбор потока интерактива; мейнтейнер может его пересмотреть на ревью спеки.

1. Отдельного определения ФВ не добавляем: термин опирается на два имеющихся предложения статьи. Новое предложение из ASE 2019 возможно позже отдельным контент-PR, без чисел.
2. Пояснения помечаем `data-pagefind-ignore`: они повторяют предложения статьи, и в поиске были бы дубли. Сама статья индексируется как раньше.
3. «Степень регургитации» не берём: градации близки к порогам для самооценки. «Регургитация» остаётся в PR 4, только если для неё найдётся источник из `content/trusted-sources.yaml`, текст которого можно открыть и сверить; иначе термин тоже не берём. Новые главы StatPearls не берём: сайт показывает проверку на бота, сверить текст нельзя (источник 4 статьи остаётся).
