# Редакционный процесс: что переносим из закрытого стека HA

Дата: 14.10.2026. Issue: #330.

## Контекст

План «редакционный процесс и интерактивные статьи» (HA-01 … HA-12) был реализован стеком черновых PR #331–#337 на базе 3d4ce3c. Стек закрыт без мерджа (причины в комментарии к #331):

- проверка рецензий в сборке запрещала публиковать новые статьи без врача, а врачей у проекта нет;
- поле `publication` по умолчанию `draft` скрыло бы все статьи, добавленные после 3d4ce3c;
- проверка порядка источников запрещала любую правку источника;
- service worker стирал офлайн-копии страниц при каждом деплое.

Главная предпосылка плана (врач-автор и врач-рецензент) пока не выполнена. Поэтому сначала делаем то, что помогает найти врача, и то, что полезно читателю уже сейчас.

## Что делаем

### PR 1. Страница «Для врачей» (этот PR)

- Страница `/<locale>/for-doctors/` во всех языках из реестра: зачем проекту врачи, три способа помочь (проверить статью, написать или дополнить статью, сообщить об ошибке), что публично, ссылки на форму и документы.
- Ссылка на страницу в подвале сайта.
- Форма GitHub Issues `physician.yml` («Врач: рецензия или статья»): роль, специальность, какие статьи, предупреждение о публичности.
- `docs/medical-author-template.md`: шаблон, по которому врач присылает материал без MDX, YAML и Git.
- `docs/medical-review.md`: как сейчас проходит рецензия. Врач читает статью на сайте и сверяет с источниками, замечания идут в issue. После правок мейнтейнер заполняет существующее поле `review: { reviewer, date }` с согласия врача, и плашка «Врачом не проверено» у статьи исчезает.
- Без новых проверок в сборке, без изменений схемы и статей.

### PR 2. Разбор заключения ЭхоКГ (отдельная спека, поток «Интерактив для статей»)

Вымышленное учебное заключение эхокардиографии: читатель выбирает термин и видит простое пояснение, уточнение для студента, ограничения и источник. Без загрузки файлов, без полей для личных значений, без норм и автоматической классификации «норма/патология». Компонент встраивается в статью напрямую, как остальные (`<ReportExplorer … />`), без sidecar-файлов. Основа кода: ветка `feat/editorial-guided-report` (#335).

### Позже. Стабильные id источников

`<Cite ref="…">` рядом с существующим `<Cite n={…}>`, без запрета править источники. Отдельная спека, когда перестановка источников станет реальной проблемой для потоков статей.

## Что откладываем до первого врача-рецензента

Поле `publication` и изъятие статей, рецензии, привязанные к версии (digest), хостинг предпросмотра, CMS (Keystatic). Возвращаемся к ним отдельной спекой после первых реальных рецензий; ветки стека остаются как справочный материал.

## Проверка PR 1

- Страница собирается для каждой локали, ссылки идут через `BASE_URL` и `localePath`, строки в `messages/<locale>.json`, CSS на логических свойствах.
- e2e: заголовок, ссылка на форму врача, ссылка из подвала, axe без нарушений.
- `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm i18n:check`, `pnpm build`, `pnpm e2e`.
